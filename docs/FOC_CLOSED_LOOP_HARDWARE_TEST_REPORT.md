本轮工作的目标是将 FOC 电流环放入 20 kHz MCPWM 定时器 ISR，并使用真实 AS5600 角度和 ADC 电流样本完成闭环控制。速度 PI 仍位于应用层任务中，`foc_core` 只负责电流环。

| 电流 O1 | 39 | ADC1 连续采样，A 相 |

| 母线电压采样 | 4 | ADC2 单次采样；驱动板已完成分压 |

| AS5600 SDA | 19 | I2C0 |

其他参数：

- 母线电压按 12 V 配置；GPIO4 分压比尚未确认，因此母线采样目前只记录，不参与实时电压补偿。
- 分流电阻 10 mΩ，INA240 增益 50 V/V，电流换算系数为 `0.002 A/mV`。
- AS5600 地址为 `0x36`，由驱动板独立供电。
- 电机额定电流约 0.5 A；当前测试保守限制相电流为 0.2 A。

## 3. 当前实时链路

```text
ADC1 Continuous + DMA（40 kS/s，两通道）
    -> ADC 读取任务（CPU0）
    -> 最新双通道无锁快照
    -> MCPWM 空载事件 ISR（CPU1，20 kHz）
    -> current Topic
    -> foc_core::core_loop_from_isr()
    -> Clarke/Park、电流 PI、反 Park、SVPWM
    -> MCPWM 三相比较器（GPIO32/33/25）

AS5600（I2C 400 kHz）
    -> 控制任务（CPU0，约 1 ms）
    -> rotor Topic
    -> MCPWM ISR 中的 FOC 电角度计算

AS5600 角度差分
    -> 应用层速度估计和速度 PI
    -> q 轴电流目标
```

### 3.1 MCPWM 与 ISR

- MCPWM 分辨率为 10 MHz，周期为 500 个计数，对应 20 kHz。
- 三个 operator、comparator 和 generator 输出三相 PWM。
- 比较值在定时器周期边界更新，三相更新由硬件同步。
- MCPWM 中断在 CPU1 执行，控制任务和 ADC 读取任务在 CPU0 执行。
- ISR 不打印、不执行 I2C、不调用 `adc_continuous_read()`，只读取已提交的 ADC 快照、发布电流样本、运行 `foc_core` 和更新 PWM。
- ISR 使用了 ESP32 FPU ISR 配置；同时关闭了与经典 ESP32 FPU ISR 不兼容的 FreeRTOS 中断回溯配置。

### 3.2 ADC

经典 ESP32 的 ADC2 不支持当前使用的 Continuous/DMA 方案，所以电流采样使用 ADC1 GPIO39 和 GPIO36。ADC 驱动产生 DMA 帧，由 CPU0 任务调用 `adc_continuous_read()` 和 `adc_continuous_parse_data()`，这部分调用方式参考了 `~/embedded_project/test/isr_test`。

ISR 不直接读取 ADC 驱动内部缓冲区，而是读取任务发布的 A/B 原始值一致性快照。快照使用版本号校验，避免双核并发写入时读到半更新数据。

### 3.3 I2C 与 AS5600 恢复

- 当前 I2C 速度为 400 kHz。
- 启用了 ESP32 内部上拉；内部上拉能够运行不代表线束抗干扰裕量已经充分。
- AS5600 读取失败时会按次数重试。
- 遇到超时、NACK 或总线错误时，会先复位 ESP32 侧 I2C 总线，再等待后重试。
- 重试仍失败时关闭控制链路，并提示重新插拔驱动板供电。

由于 AS5600 独立供电，ESP32 重新烧录或复位时，传感器可能仍保持异常状态。软件总线复位只能处理 ESP32 侧和线路状态，不能代替 AS5600 断电重启。

## 5. 已获得的硬件证据

### 5.1 20 kHz ISR 本身

此前长测中，MCPWM ISR 持续运行约 60 s，计数接近 120 万次，期间没有出现 ISR 控制周期故障、AS5600 读取失败或 ADC 数据中断。运行日志中的 ISR 周期峰值约为 11,772 个 CPU 周期，在 240 MHz 下约为 49.1 μs；其他运行中曾出现约 13,815 个周期，约 57.6 μs。

因此当前 ISR 虽然能够运行，但最坏情况已经接近甚至超过 20 kHz 的 50 μs 周期预算，后续仍需要优化和测量中断抖动。这个结果不能解释为“20 kHz ISR 本身不能工作”。

### 5.2 真实角度闭环

已经确认以下调用链实际执行：

1. AS5600 角度读取成功。
2. 传感器对齐并计算电角度零点。
3. AS5600 机械角度发布到 `rotor Topic`。
4. ADC 电流样本由 20 kHz ISR 发布到 `current Topic`。
5. `foc_core::core_loop_from_isr()` 返回正常结果并更新 PWM。
6. 运行状态中 `Iq` 能跟踪 `Iq_target`。

用户在长测结果前后目视观察到过一次电机非常流畅地连续旋转。这是重要的实机证据，说明当时整条控制链至少曾经进入过有效的闭环旋转状态；但当时没有保存一份能够对应到该次旋转的完整串口日志，因此暂时不能把它当作已经稳定复现的验收结果。

### 5.3 未能稳定复现的运行

在随后几次同类复测中，电机出现了以下情况：

- q 轴目标约 `0.05 A` 时，电机可能只移动很小角度后保持。
- 将测试方向改为商家 ESP32 示例中的 `-1` 后，曾出现约 `0.11 rad` 的机械角移动，但仍未连续旋转。
- 对齐电压改为 `0.8 V` 后，未观察到明显改善，随后已恢复到安全基线 `0.4 V`。
- q 轴目标提高到 `0.08 A` 时，电流能够跟踪到约 `0.08 A`，但该次仍未连续转动。
- q 轴目标提高到 `0.15 A` 时，约 1.2 s 后触发过流保护；日志显示 `Ib≈0.229 A`、`Ic≈-0.230 A`，故障位为 `0x4`。该实验参数已恢复，没有保留在当前安全基线中。

这些失败复测只能说明启动条件尚不稳定，不能推翻此前那次顺畅旋转，也不能单独证明是 ISR 的问题。

## 6. 当前判断

### 已确认

- 20 kHz MCPWM ISR 可以持续执行。
- ADC 任务读取/解析与 ISR 消费的分工可以稳定工作。
- I2C 400 kHz 下 AS5600 可以正常读取；已有总线复位和重试路径。
- 真实 AS5600 角度确实进入了 FOC 电角度计算。
- q 轴电流环能够输出并跟踪低电流目标。
- 软件过流保护能够在相电流超过 0.2 A 时停机。

### 尚未确认

- 每次上电后都能可靠起转。
- 当前方向、相序和电流符号组合已经是最终正确组合。
- 20 kHz ISR 最坏执行时间满足长期产品运行裕量。
- 当前速度 PI 和低电流限幅能够覆盖电机的启动静态转矩及齿槽转矩。
- 当前 ADC 采样时刻与 PWM 中点之间的关系足够稳定。

目前最合理的结论是：**20 kHz ISR 运行能力已通过实机长测；真实角度闭环旋转曾经成功出现，但启动和连续运行的可重复性仍需继续定位。**

## 7. 下一步建议

1. 在保留 20 kHz MCPWM ISR 的前提下增加一个很短的开环电角度旋转对照，用来单独验证 MCPWM 三相输出、相序和电压极性。
2. 对照开环结果检查 `PWM A/B/C` 相序、AS5600 方向、零点计算和电流符号，不再只通过提高 q 轴电流来试错。
3. 保持 `0.2 A` 相电流保护，暂不把 `0.15 A` 以上测试值作为默认参数。
4. 将 ADC 采样进一步和 PWM 周期边界或中点同步，并记录电流峰值、`Iq`、`Iq_target`、`u_q` 和电角度。
5. 将 ISR 周期峰值压到 50 μs 以下并保留余量；当前约 49 μs 的观测值已经过于接近预算。
6. 如果再次出现 AS5600 通讯异常，先观察软件总线复位和重试结果；仍失败时重新插拔驱动板供电，再重新烧录或复位 ESP32。
