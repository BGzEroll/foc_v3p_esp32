本报告记录 20 kHz 基线和当前 10 kHz 降频版本。两者都将 FOC 电流环放入 MCPWM 定时器 ISR，并使用真实 AS5600 角度和 ADC 电流样本完成闭环控制。速度 PI 仍位于应用层任务中，`foc_core` 只负责电流环。

- 电机额定电流约 0.5 A；当前测试保守限制相电流为 0.2 A。

## 3. 当前实时链路

```text
ADC1 Continuous + DMA（40 kS/s，两通道）
    -> ADC 读取任务（CPU0）
    -> 最新双通道无锁快照
    -> MCPWM 空载事件 ISR（CPU1，当前 10 kHz；20 kHz 为历史基线）
    -> current Topic
    -> foc_core::core_loop_from_isr()
    -> Clarke/Park、电流 PI、反 Park、SVPWM
    -> MCPWM 三相比较器（GPIO32/33/25）

AS5600（I2C 400 kHz）
    -> 控制任务（CPU0，约 1 ms）
    -> rotor Topic
    -> MCPWM ISR 中的 FOC 电角度计算

AS5600 角度差分
    -> 应用层速度估计和速度 PI
    -> q 轴电流目标
```

### 3.1 MCPWM 与 ISR

- 当前 MCPWM 分辨率为 10 MHz，周期为 1000 个计数，对应 10 kHz；此前 20 kHz 版本使用 500 个计数。
- 三个 operator、comparator 和 generator 输出三相 PWM。
- 比较值在定时器周期边界更新，三相更新由硬件同步。
- MCPWM 中断在 CPU1 执行，控制任务和 ADC 读取任务在 CPU0 执行。
- ISR 不打印、不执行 I2C、不调用 `adc_continuous_read()`，只读取已提交的 ADC 快照、发布电流样本、运行 `foc_core` 和更新 PWM。
- ISR 使用了 ESP32 FPU ISR 配置；同时关闭了与经典 ESP32 FPU ISR 不兼容的 FreeRTOS 中断回溯配置。

### 3.2 ADC

经典 ESP32 的 ADC2 不支持当前使用的 Continuous/DMA 方案，所以电流采样使用 ADC1 GPIO39 和 GPIO36。ADC 驱动产生 DMA 帧，由 CPU0 任务调用 `adc_continuous_read()` 和 `adc_continuous_parse_data()`，这部分调用方式参考了 `~/embedded_project/test/isr_test`。

ISR 不直接读取 ADC 驱动内部缓冲区，而是读取任务发布的 A/B 原始值一致性快照。快照使用版本号校验，避免双核并发写入时读到半更新数据。

### 3.3 I2C 与 AS5600 恢复

- 当前 I2C 速度为 400 kHz。
- 启用了 ESP32 内部上拉；内部上拉能够运行不代表线束抗干扰裕量已经充分。
- AS5600 读取失败时会按次数重试。
- 遇到超时、NACK 或总线错误时，会先复位 ESP32 侧 I2C 总线，再等待后重试。
- 重试仍失败时关闭控制链路，并提示重新插拔驱动板供电。

由于 AS5600 独立供电，ESP32 重新烧录或复位时，传感器可能仍保持异常状态。软件总线复位只能处理 ESP32 侧和线路状态，不能代替 AS5600 断电重启。

## 5. 已获得的硬件证据

### 5.1 20 kHz ISR 本身

此前长测中，MCPWM ISR 持续运行约 60 s，计数接近 120 万次，期间没有出现 ISR 控制周期故障、AS5600 读取失败或 ADC 数据中断。运行日志中的 ISR 周期峰值约为 11,772 个 CPU 周期，在 240 MHz 下约为 49.1 μs；其他运行中曾出现约 13,815 个周期，约 57.6 μs。

因此当前 ISR 虽然能够运行，但最坏情况已经接近甚至超过 20 kHz 的 50 μs 周期预算，后续仍需要优化和测量中断抖动。这个结果不能解释为“20 kHz ISR 本身不能工作”。

### 5.2 真实角度闭环

已经确认以下调用链实际执行：

1. AS5600 角度读取成功。
2. 传感器对齐并计算电角度零点。
3. AS5600 机械角度发布到 `rotor Topic`。
4. ADC 电流样本由 MCPWM ISR 发布到 `current Topic`。
5. `foc_core::core_loop_from_isr()` 返回正常结果并更新 PWM。
6. 运行状态中 `Iq` 能跟踪 `Iq_target`。

用户在长测结果前后目视观察到过一次电机非常流畅地连续旋转。这是重要的实机证据，说明当时整条控制链至少曾经进入过有效的闭环旋转状态；但当时没有保存一份能够对应到该次旋转的完整串口日志，因此暂时不能把它当作已经稳定复现的验收结果。

### 5.3 未能稳定复现的运行

在随后几次同类复测中，电机出现了以下情况：

- q 轴目标约 `0.05 A` 时，电机可能只移动很小角度后保持。
- 将测试方向改为商家 ESP32 示例中的 `-1` 后，曾出现约 `0.11 rad` 的机械角移动，但仍未连续旋转。
- 对齐电压改为 `0.8 V` 后，未观察到明显改善，随后已恢复到安全基线 `0.4 V`。
- q 轴目标提高到 `0.08 A` 时，电流能够跟踪到约 `0.08 A`，但该次仍未连续转动。
- q 轴目标提高到 `0.15 A` 时，约 1.2 s 后触发过流保护；日志显示 `Ib≈0.229 A`、`Ic≈-0.230 A`，故障位为 `0x4`。该实验参数已恢复，没有保留在当前安全基线中。

### 5.4 本次 4 V 电压上限复测

- 将 `MOTOR_VOLTAGE_LIMIT_V` 从 `2.0 V` 提高到 `4.0 V`，未提高 q 轴目标电流，仍保持 `0.05 A` 启动目标和 `0.2 A` 相电流保护。
- 现场观察到电机能够顺畅旋转，因此本次没有继续烧录之前的非中断任务版固件。
- 同一轮串口记录出现一次异常速度值 `-30.411 rad/s`，随后触发软件速度保护；这与现场目视观察不完全一致，暂时只能作为 AS5600 角度展开、速度差分或日志时序问题的待核对证据，不能据此判定电机未旋转。

这些失败复测只能说明启动条件尚不稳定，不能推翻此前那次顺畅旋转，也不能单独证明是 ISR 的问题。

### 5.5 修复传感器对齐载波时序后的 20 kHz 复测

复核启动流程后发现，原流程在 `align_sensor()` 中写入对齐占空比时，MCPWM 定时器尚未执行 `mcpwm_timer_enable()` 和启动操作。因此对齐电压可能没有真正施加到电机，电气零点会依赖转子当时的随机位置，造成同一组参数有时能转、有时只能小角度抖动。

本次修改如下：

- 在传感器对齐前完成 20 kHz MCPWM 定时器回调注册和定时器使能。
- 对齐期间单独启动 PWM 载波，但保持 `control_timer_running=false`，MCPWM ISR 不运行 FOC 核心。
- 先写入 0.4 V 对齐电压，再打开 EN；对齐完成后关闭 EN 和载波。
- 正式进入速度闭环时仍使用原来的 `start_control_timer()`。

修复后没有修改速度滤波参数和闭环电流参数，实测串口结果如下：

- `MOTOR_VOLTAGE_LIMIT_V=4.0 V`、`SPEED_FILTER_ALPHA=0.5`、q 轴限幅 `0.05 A`、启动助推 `0.05 A/100 ms`。
- 约 1.9 s 进入速度闭环，之后机械角从约 `2.87 rad` 连续增加到约 `91.47 rad`。
- `speed_window` 约 `2.4–3.5 rad/s`，即约 `23–33 rpm`；目标为 `5.0 rad/s`。
- `rotor_seq` 持续递增，`enc_reject=0`，未出现 FOC 故障或速度保护停机。
- 本次监控持续约 30 s，说明 20 kHz ISR 和真实 AS5600 角度闭环已经能够重复进入连续运行状态；电机仍有轻微顿挫，后续再单独优化速度反馈和速度 PI。

### 5.6 20 kHz 版本的速度反馈调参与斜率限制试验

在传感器对齐时序修复后的基础上，先将速度反馈滤波从 `Alpha=0.1` 调整为 `Alpha=0.05`，并保持滤波器只在新的 20 ms 速度估计窗口到达时更新，避免控制任务每 1 ms 重复对同一速度样本滤波。

当前参数完成约 60 s 自动闭环测试：

- `MOTOR_VOLTAGE_LIMIT_V=4.0 V`、`SPEED_FILTER_ALPHA=0.05`、速度估计窗口 `20 ms`。
- q 轴限幅仍为 `0.05 A`，启动助推仍为 `0.05 A/100 ms`。
- 运行计数约 `1,179,986` 次，机械角度增量约 `213.963 rad`，`enc_reject=0`，无 FOC 故障和速度保护停机。
- 本次 ISR 峰值为 `12,823` 个 CPU 周期；在 240 MHz 下约 `53.4 us`。这次运行连续，但峰值仍略超 20 kHz 的 `50 us` 周期预算。
- 速度窗口大多在约 `2–5 rad/s`，速度反馈和 q 轴目标的负向反拉较此前减少；从控制量趋势看，`Alpha=0.05` 是当前较合适的安全参数，但机械细微顿挫仍需现场观察或波形进一步确认。

随后试验性加入 `0.5 A/s` 的 q 轴目标斜率限制。该限制确实减小了单次目标跳变，但约 26–28 s 出现了“转动—近似停住—再次加速”的周期性现象，因此已撤销，不保留在当前代码中。

### 5.7 20 kHz 版本的固件资源与实时余量

最终接受版固件的 `idf.py size --format json2` 结果如下：

| 资源 | 已使用 | 总量 | 剩余 | 判断 |
| --- | ---: | ---: | ---: | --- |
| 应用分区 | `0x39380` 字节 | `0x100000` 字节 | `0xc6c80` 字节，约 78% | Flash 空间充足 |
| IRAM | `58,083` 字节 | `131,072` 字节 | `72,989` 字节，约 55.7% | 中断代码空间充足 |
| DRAM | `19,774` 字节 | `180,736` 字节 | `160,962` 字节，约 89.1% | 数据空间充足 |

ESP32 当前运行在 240 MHz。20 kHz 控制周期只有 `50 μs`，相当于 `12,000` 个 CPU 周期；常态 ISR 记录大多约为 `7,300–9,000` 个周期，但历史峰值达到 `13,747` 个周期，约 `57.3 μs`；20 kHz 接受版本本轮峰值为 `12,823` 个周期，约 `53.4 μs`。因此 20 kHz 版本的主要余量问题不是存储器，而是 ISR 最坏执行时间和中断抖动。当前工程仍使用 Debug/Default 编译优化，后续可在保持行为一致的前提下单独评估性能优化构建。

### 5.8 10 kHz 降频复测

在保留 4 V 电压上限、`SPEED_FILTER_ALPHA=0.05`、20 ms 速度估计窗口、0.05 A q 轴限幅和 0.2 A 相电流保护的前提下，将 PWM 和 FOC 电流环同时从 20 kHz 降至 10 kHz。FOC 控制周期同步改为 `100 μs`，ADC 连续采样仍保持 `40 kS/s`，电流 PI 的 `Kp=0.54`、`Ki=400` 暂不调整。

10 kHz 版本完成约 60 s 自动闭环测试：

- 启动日志确认 `PWM=10000 Hz`、`FOC=10000 Hz`，AS5600 读取和对齐均正常。
- 运行计数约 `589,993` 次，机械角度增量约 `177.531 rad`，`enc_reject=0`，无 FOC 故障和速度保护停机。
- 运行期间角度持续增加，统计平均机械速度约 `3.0 rad/s`；速度窗口大多约 `2–4 rad/s`，目标仍为 `5.0 rad/s`。
- ISR 峰值为 `10,894` 个 CPU 周期，在 240 MHz 下约 `45.4 μs`；相对 10 kHz 的 `100 μs` 周期，按本轮峰值计算约有 `54.6 μs` 的即时余量。
- 10 kHz 已证明可以连续闭环运行，实时余量明显优于 20 kHz；但仅凭串口统计还不能断言机械顺滑度一定优于 20 kHz，低速细微顿挫仍需结合现场观察或电流/速度波形确认。

## 6. 当前判断

### 已确认

- 20 kHz MCPWM ISR 可以持续执行；当前 10 kHz MCPWM ISR 也已通过约 60 s 实机运行。
- ADC 任务读取/解析与 ISR 消费的分工可以稳定工作。
- I2C 400 kHz 下 AS5600 可以正常读取；已有总线复位和重试路径。
- 真实 AS5600 角度确实进入了 FOC 电角度计算。
- q 轴电流环能够输出并跟踪低电流目标。
- 软件过流保护能够在相电流超过 0.2 A 时停机。
- 将 FOC 电压上限提高到 4 V 后，现场观察到电机顺畅旋转；该次运行的速度诊断记录存在异常值，仍需补充原始角度和样本时序。
- 修复对齐阶段未启动 MCPWM 载波的问题后，10 kHz 版本在 `SPEED_FILTER_ALPHA=0.05`、20 ms 速度估计窗口和 q 轴限幅 `0.05 A` 下，已通过约 60 s 连续闭环运行复测。
- 速度反馈滤波改为按 20 ms 新样本节奏更新后，当前闭环运行的速度环目标变化较缓和；试验性的 q 轴目标斜率限制因产生周期性近停转已撤销。

### 尚未确认

- 每次上电后都能可靠起转。
- 当前方向、相序和电流符号组合已经是最终正确组合。
- 当前 10 kHz ISR 在本轮测试中有明显周期余量，但更长时间和不同系统负载下的最坏执行时间仍需确认；20 kHz 版本没有正的最坏路径余量。
- 当前速度 PI 和低电流限幅能够覆盖电机的启动静态转矩及齿槽转矩。
- 当前 ADC 采样时刻与 PWM 中点之间的关系足够稳定。

目前最合理的结论是：**当前 10 kHz PWM/FOC 电流环和真实 AS5600 角度闭环已经通过约 60 s 无故障连续运行验证，4 V 电压上限、`SPEED_FILTER_ALPHA=0.05`、20 ms 速度估计窗口和 0.05 A q 轴限幅可以作为当前安全测试参数。10 kHz 的 ISR 实时余量明显好于 20 kHz；当前主要剩余问题是低速下仍有轻微顿挫，以及实际速度尚未稳定达到 5 rad/s 目标。**

## 7. 下一步建议

1. 在保留当前 10 kHz MCPWM ISR 的前提下增加一个很短的开环电角度旋转对照，用来单独验证 MCPWM 三相输出、相序和电压极性。
2. 对照开环结果检查 `PWM A/B/C` 相序、AS5600 方向、零点计算和电流符号，不再只通过提高 q 轴电流来试错。
3. 保持 `0.2 A` 相电流保护，暂不把 `0.15 A` 以上测试值作为默认参数。
4. 将 ADC 采样进一步和 PWM 周期边界或中点同步，并记录电流峰值、`Iq`、`Iq_target`、`u_q` 和电角度。
5. 当前 10 kHz 峰值约 45.4 μs，已低于 100 μs 周期；后续若恢复 20 kHz，仍需将峰值压到 50 μs 以下并保留余量。
6. 如果再次出现 AS5600 通讯异常，先观察软件总线复位和重试结果；仍失败时重新插拔驱动板供电，再重新烧录或复位 ESP32。
